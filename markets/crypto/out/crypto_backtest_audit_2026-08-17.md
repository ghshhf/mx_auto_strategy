# 加密回测基线审计（2026-08-17）

> 触发：用户怀疑当前引擎 10y 绝对倍数（报告展示 44M~59.4Mx、reconcile 测到 3.7亿x）"基线不对"。

## 五、引擎 bug 精确定位

### Bug A：put 保险层被建模成收益引擎
- 位置：`crypto_options_bt.py` 第 660–692 行
- 机制：每周扣小额保费 `put_cost_weekly_bps`；但每次单币周跌超 `put_single_crash` 阈值，即按 `cw × nav × put_single_payout_ratio × severity` 加回 nav。
- 反常：关掉该层后倍率 **3.7亿→18万（Δ-100%）**。真实保险是净成本，关掉应让倍率上升或持平；此处反向下跌，说明赔付基数/payout_ratio 远超保费，暴跌周"印钱"在 10y 复利里爆炸。属前视/超配类建模错误。

### Bug B：`alloc_offense_mult=1.2` 杠杆被包装成"选币优化"
- 位置：第 1005–1010 行；默认值在 DEFAULT_CFG（第 206 行）
- 机制：把进攻仓位 `offense × 1.2`（从现金里扣），即**杠杆**（git 历史 b3b1960 注释自承"Sharpe 不变"）。
- 反常：注释声称 +774%（8.7x 倍率比），reconcile 实测 **18.12x**。1.2x 杠杆在赢家选币 10y 复利里被放大到 18x，被提交信息包装成"选币逻辑优化 +774%"。

## 六、git 历史：虚高逐步累积

- `b3b1960`（2026-08-13）：`alloc_offense_mult 1.0→1.2` + `offense_weight_mode→inv_vol`，提交称 10y **6.8K→59.4M（+774%）**。本次把引擎推到千万倍级。
- 但 **6.8K 本身已偏高**（买入持有才 14x）→ 虚高是多次"优化"累积，非一次引入。
- README/param/config 注释里倍率早已碎片化：README 28,092x / param 6.79Mx / config 59,361Kx（reconcile_truth.py 头部自陈此问题）。

## 八、对之前"删/加币影响"结论的修正

- 之前报的"删 SUI/CRV：10y −25% / 5y +4% / 3y −7%；COMP→BCH：10y +13% / 5y −5%"——这些是**同一虚高引擎下的相对差异**。
- 定性结论（方向随机、幅度小、二阶噪声）**仍然成立**（A/B 用同一引擎，相对反应不受绝对虚高影响）。
- 但**精确倍数不可信**，且若 put 层 bug 对不同币的暴跌赔付频率敏感，则个别币的精确边际也可能失真。建议：引擎 reconcile 后重跑，相对影响结论大概率不变。

## 九、下一步建议（需用户拍板，未改动引擎）

1. **修 Bug A**：put 保险层改为真对称（赔付封顶=已付保费 × 合理倍数，或默认 `enabled_put=False`），重跑看倍数回落到哪。
2. **回退 Bug B**：`alloc_offense_mult` 默认回 `1.0`（或显式标注为杠杆、不计入"选币 alpha"）。
3. **对外报数一律用地面真相锚点**（买入持有 14x / BTC 108x）做 sanity check，任何 >1000x 的 10y 结果直接判虚高。
4. 若要保留"期权收益覆盖层"叙事，须先证明 put 层在 OOS/样本外不印钱（跑 `crypto_oos_validate.py` / `robustness_check.py`）。
