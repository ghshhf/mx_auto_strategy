## 四、发现的问题 (均不阻塞本次修复)

### P1 数据层列错位 — 面板跑的是「周最低价」不是「周收盘价」(既有缺陷, 早于本次修复)

`eastmoney_hfq_rebuild.py:90` 请求 `fields2=f51,f53,f55,f56,f57,f58,f59,f60,f61`
= 日期,**收盘**,**最低**,成交量,成交额,振幅,涨跌幅,涨跌额,换手率
但 `fetch_one()` 按 `p[1]=开盘 p[2]=收盘 p[3]=最高 p[4]=最低` 解析并以
`(d,o,h,l,c,v,a)` 落盘 → 列标签整体错位。

实测证据 (71,868 行, 105 只 A 股 + 00388):
- 文件 `open` 列环比涨跌幅 == 文件 `amount` 列: **100.00%**
- 文件 `close` 列环比涨跌幅 == `amount` 列: 5.38%
- `close <= open` (最低<=收盘应恒真): **100.00%**, 违反 0 行
- 标准 OHLC 自洽率: A 股 **0.0%** vs 腾讯抓的 19 只港股 **100.0%**

→ 文件 `open`=真收盘, `close`=真最低, `amount`=真涨跌幅%。
而 `build_panel()` 读的是 `row["close"]` → **面板 100% 取到周最低价**(抽样 2907 单元格验证)。

影响:
1. A 股侧全部回测跑在周最低价序列上, 港股侧(19只)跑在周收盘价上 —— **同一面板内口径不一致**;
2. 这正是 IPO"伪迹"的**真正成因**: 300750 首周面板 30.17→58.30 = +93.2%, 而真实收盘 53.00→66.55 仅 **+25.6%**;
3. 本次防火墙修复方向正确、必要且有效, 但属于症状层治理; 根因在数据管道, 建议单独立项。

### P2 `run_three_ways.py` 把「末期回撤」当「MDD」上报 (报表口径 Bug)

`extract_10y()` 取 `rows[-1]["dd_10y_opt"]` —— 那是**最后一周的回撤值**, 不是最大回撤。
实测: fused/pure_a 上报 -5.4% (真实 MDD -22.2%), pure_hk 上报 -1.3%/+0.0% (真实 -24.7%/-22.7%)。
修法: 改成 `min(所有行 dd)`。不影响引擎, 但会误导决策。

### P3 `_FIRST_LISTED_CACHE` 无淘汰, 长驻进程内存单调增长 (轻微)

缓存以 `id(list)` 为 key 且持有强引用, 每次 `load_panel()` 生成全新列表 →
实测连续 3 次 load_panel 后条目 125→250→375, 只增不减。
当前规模(125列)影响可忽略, 但 live 长驻进程 / 批量扫参会持续膨胀。
建议: 在 `load_panel()` 内一次性预计算并随面板返回, 或每次 load 时 `clear()`。
